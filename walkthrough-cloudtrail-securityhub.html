// Project Walkthrough · 08
AWS Security Services Baseline

A Terraform baseline that stands up AWS's account-level compliance backbone: multi-region CloudTrail with log-file validation, and Security Hub subscribed to NIST 800-53 Rev 5 and AWS Foundational Security Best Practices. Unlike the per-resource primitives elsewhere in the toolkit, these are singleton account services, applied by hand in a sandbox, evidence captured and signed, then torn down before Security Hub's per-check billing adds up.

terraform aws cloudtrail security hub cosign nist 800-53 rev 5 · fedramp moderate
Problem Statement
01

A Terraform primitive like compliant-s3 proves a resource was compliant at the moment it was planned and applied. It doesn't keep proving anything once the PR merges. Auditors don't just want a snapshot at deploy time. They want continuous evidence that the account is still behaving the way it was configured to.

CloudTrail and Security Hub are the layer that keeps producing that evidence after nobody is pushing PRs anymore. CloudTrail records what happened: every management-plane API call, signed and tamper-evident. Security Hub aggregates what's currently wrong: findings from every subscribed standard, normalized into one view instead of five different consoles.

What It Deploys
02
// AU-2 / AU-12
Multi-Region Management Trail
is_multi_region_trail = true and include_global_service_events = true mean an API call in any region, or a global-service event like an IAM change, lands in the same trail. No blind spots from a region-scoped default.
// AU-10
Log-File Validation
enable_log_file_validation = true makes CloudTrail emit an hourly digest file signed with an AWS-managed key. Any tampering with a delivered log file breaks the digest chain: non-repudiation, not just delivery.
// RA-5 / SI-4
Security Hub: NIST 800-53 + FSBP
Subscribes the account to two standards simultaneously. Security Hub's control evaluation runs continuously in the background. This isn't a one-time scan, it's ongoing monitoring that keeps generating findings as the account drifts.
// CM-2 / CM-6 / CM-8
Config: Inherited, Not Deployed
This module's own Config resources are written but disabled. See the wrinkle below. The account's pre-existing recorder stands as the evidence instead.
Real-World Wrinkles
03

Three things came up mid-build that a clean lab writeup wouldn't mention. All three ended up being about telling a transient AWS/Terraform hiccup apart from a real problem before reaching for a destructive fix.

wrinkle 1 · config.tf
One Config Recorder Per Region, Account Already Had One
The sandbox account already had an AWS-managed default Config recorder using the service-linked role AWSServiceRoleForConfig, predating this session, and AWS allows exactly one recorder per region. Deleting infrastructure with an unknown origin wasn't an option. Block-commented this module's own Config resources and let the account's existing recorder stand as the CM-2/CM-6/CM-8 evidence instead, the same remedy the lab's own SCP-blocked scenario prescribes for a different root cause.
wrinkle 2 · cloudtrail.tf
False "+create" Diff Seconds After a Clean Apply
terraform plan rendered the CloudTrail bucket as a brand-new + create moments after it had already applied successfully, cascading false diffs onto every resource that referenced it. terraform state show against the on-disk state proved the entry was fully populated. Nothing was lost. It was a refresh-only artifact of S3 eventual consistency in us-east-1 racing the plan. Re-ran the plan and it cleared. No state surgery needed for a problem that didn't exist.
wrinkle 3 · security_hub.tf
"Tainted" Subscriptions That Were Actually Healthy
Both Security Hub standards subscriptions hit Terraform's 3-minute waiter timeout during first-time activation and came back marked tainted. aws securityhub get-enabled-standards confirmed both were already READY in AWS: the waiter gave up before AWS finished, not because anything failed. terraform untaint cleared the flag without an unnecessary unsubscribe/resubscribe cycle, which for Security Hub means resetting the findings-population clock for no reason.

// evidence handling
The findings, CloudTrail status, and hub metadata were bundled, SHA-256 hashed, and signed with cosign sign-blob (keyless, Sigstore OIDC), the same signing pattern Lab 4.4 established, then uploaded to the evidence vault with a receipt. The account ID in the committed evidence JSON is redacted for public repo visibility; the unredacted signed original is the vault copy the receipt points to.
Key Technical Decisions
05
DecisionReasoning
Config block-commented, not deleted or forcedThe account's default recorder's service-linked role is a strong signal it predates this session. AWS's one-recorder-per-region limit means ours could never coexist with it anyway.
terraform untaint over destroy/recreateget-enabled-standards confirmed both subscriptions were already READY. Untainting fixes Terraform's bookkeeping without resetting the findings-population clock.
Re-plan instead of state rm/importterraform state show proved the on-disk state was fully intact. The false diff was a refresh-only artifact, not real state loss.
Manual sign-and-upload, not wired into grc-gate.ymlThese are account-level singleton services, not per-PR resources. Running this in CI would apply real Security Hub/Config spend on every pull request.
No Rego/Conftest policies addedNothing re-evaluates this config on a recurring trigger the way grc-gate.yml does for compliant-s3. Policy-as-code has no consumer here yet.
